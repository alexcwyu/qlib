# Development

## Maintained uv environment (2026-10-12)

The tested interpreter selection is Python 3.14.8. uv 0.13.0 resolves runtime dependencies, optional extras, development groups, and build isolation. `uv.lock` records exact versions; `--upgrade` refreshes them within the project and compatibility constraints. Review [validation evidence](validation.md) before treating a build or test command as successful on this host.

Python 3.15 resolves metadata, but torch 2.14.1 has no matching CPython 3.15 wheel. Python 3.14.8 builds the Cython extensions and installs the complete environment.

### Layout and build ownership

The upstream qlib/ Python and Cython layout is retained. setup.py defines native extensions and pyproject.toml defines metadata and build isolation. Moving the package would also require relocating extension paths, so this maintenance updates uv configuration without mass-moving native sources.

Apple Command Line Tools and compiler headers are required when a dependency or extension builds from source.

### Commands from the repository root

```sh
uv python install 3.14.8
uv lock --upgrade --python 3.14.8
uv sync --all-groups --all-extras --python 3.14.8
uv build
uv run --no-sync python scripts/get_data.py download_data --file_name v2/qlib_data_simple_cn_1d_latest.zip --target_dir ~/.qlib/qlib_data/cn_data --delete_old False
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 uv run --no-sync pytest tests
```

### External inputs and test scope

Data fixtures and provider directories are required by integration tests. Redis, MongoDB task management, MLflow storage, and downloadable datasets remain optional service boundaries. Rolling and expanding calculations are compiled C++ extensions generated by Cython, so compiler and NumPy headers are native build requirements.

Existing upstream skips and xfails remain unchanged. Full suite failures, incomplete runs, and supplemental scoped checks are listed separately in validation. No new test cases were added. The architecture document links existing implementation files and explains the component contracts.

## Compatible security and multiprocessing boundaries

Pandas 3 timezone pickles require `builtins.getattr`, which the existing security
suite expressly forbids. The compatible lock therefore selects Pandas 2.3.3
(`pandas<3`) rather than widening the global allowlist. Explicit current public
Pandas/Arrow in-memory reconstruction names are allowed; dangerous globals remain
rejected by the unchanged security cases. Tianshou 0.4.11 is the newest compatible
release for Qlib's four-value Gym environment contract; 0.5 switches to Gymnasium's
reset and step contracts. Both failed latest-version attempts are retained.

On spawn platforms, DataQueue shares manager queue/value/lock proxies instead of
unpicklable shared ctypes. Only the producer process owns cleanup; worker copies do
not tear down the shared queue. Environment factories capture worker inputs rather
than the trainer/model, and dynamically bound environment references are removed
when reward and interpreter objects cross the process boundary.

The unchanged CI commands supply both required datasets without removing existing
content:

```bash
uv run --no-sync python scripts/get_data.py download_data --file_name v2/qlib_data_simple_cn_1d_latest.zip --target_dir ~/.qlib/qlib_data/cn_data --delete_old False
uv run --no-sync python scripts/get_data.py download_data --file_name rl_data.zip --target_dir tests/.data/rl --delete_old False
MLFLOW_ALLOW_FILE_STORE=true uv run --no-sync pytest
```

The MLflow opt-in name above is taken from the repository's CI and the installed
MLflow exception. An earlier attempted `MLFLOW_ENABLE_FILE_SYSTEM_STORE` flag did
not enable the backend and its failed run remains in validation evidence.


## Native pool ownership and current policy batches

The existing DDGDA workflow fixture sets LightGBM's `num_threads` to one with
pytest's restoring monkeypatch. It retains every dataset, tree, iteration,
prediction and replay assertion; all 17 existing DDGDA cases pass. Its production
20-thread example remains unchanged. Both Python 3.14 and a Python 3.13 control
previously crashed in that workflow, so 3.13 is not a validated fallback.

Qlib's PPO wrapper supplies an empty `info` field when an observation-only batch
has no environment metadata. Current Tianshou requires that field even when the
Qlib actor ignores it. Existing metadata and state remain intact, and all 12
existing simple order-execution cases pass with this adaptation.

The same native-pool ownership is explicit in the copied online-update and
pipeline fixture tasks. The canonical suite reached all 17 DDGDA passes before a
second native crash in the online-update fixture; its failed result is retained.
The shared 20-worker example templates remain unchanged, and fixture copies keep
all tree counts, dates, replay and prediction comparisons.


The final canonical run exposed Plotly7 removing `figure_factory.create_distplot`;
analysis resolves the newest compatible Plotly6 release. CI constraints now match
the current package metadata, retain the specifically documented bad-release
exclusions, and preserve the Windows-only lxml wheel bound. All five OS jobs cover
both supported interpreters, Python 3.13 and 3.14, with native solver imports on every
Windows job. Existing collector tests count precisely the security consent warning;
