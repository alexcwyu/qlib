Maintained uv environment (2026-10-12)

The tested interpreter selection is Python 3.14.8. uv 0.13.0 resolves runtime dependencies, optional extras, development groups, and build isolation. uv.lock records exact versions; --upgrade refreshes them within the project and compatibility constraints. Review validation evidence before treating a build or test command as successful on this host.

Python 3.15 resolves metadata, but torch 2.14.1 has no matching CPython 3.15 wheel. Python 3.14.8 builds the Cython extensions and installs the complete environment.

Layout and build ownership

The upstream qlib/ Python and Cython layout is retained. setup.py defines native extensions and pyproject.toml defines metadata and build isolation. Moving the package would also require relocating extension paths, so this maintenance updates uv configuration without mass-moving native sources.

Data fixtures and provider directories are required by integration tests. Redis, MongoDB task management, MLflow storage, and downloadable datasets remain optional service boundaries. Rolling and expanding calculations are compiled C++ extensions generated by Cython, so compiler and NumPy headers are native build requirements.

Existing upstream skips and xfails remain unchanged. Full suite failures, incomplete runs, and supplemental scoped checks are listed separately in validation. No new test cases were added. The architecture document links existing implementation files and explains the component contracts.

Compatible security and multiprocessing boundaries

Pandas 3 timezone pickles require builtins.getattr, which the existing security suite expressly forbids. The compatible lock therefore selects Pandas 2.3.3 (pandas<3) rather than widening the global allowlist. Explicit current public Pandas/Arrow in-memory reconstruction names are allowed; dangerous globals remain rejected by the unchanged security cases. Tianshou 0.4.11 is the newest compatible release for Qlib's four-value Gym environment contract; 0.5 switches to Gymnasium's reset and step contracts. Both failed latest-version attempts are retained.

On spawn platforms, DataQueue shares manager queue/value/lock proxies instead of unpicklable shared ctypes. Only the producer process owns cleanup; worker copies do not tear down the shared queue. Environment factories capture worker inputs rather than the trainer/model, and dynamically bound environment references are removed when reward and interpreter objects cross the process boundary.
